# 月面档案悬停：结构决策与验证

## 方案判断

采用 A：把原 02 月面档案移动到 20 km 相对落点高度的中间态，保留六幕及编号。原档案幕的信息语言与“先读图、再进入月面”直接相关；另加第七幕会重复解释观测尺度，并加重导航。没有把极区挪来，避免南极与 Taurus–Littrow 落点之间发生地理跳跃。

原 02 锚点为内部 0.18（仍在全球视角），现在为 0.345。原 03 锚点为 0.50，现在为 0.535，明确落在 2.1 m 的稳定眼高段。04、05、06 内部锚点维持 0.68、0.84、1。所有导航、文案、相机使用同一叙事时钟。

## 新滚动结构

百分比均为实际 `scrollY / (documentHeight - innerHeight)`。页面高 1420svh，比之前增加 160svh；新增行程只在内部 0.29–0.41 分配。该窗口用平滑密度积分映射，因此入口出口没有速度阶跃；旧下降额外预算仍保留。总可滚动行程由 1160svh 增加到 1320svh，后面章节的物理滚动距离不变，百分比因总长变化而更新。

## 实现与界限

- 高度采用原来的对数空间单调 Hermite 曲线，20 km 两端等值产生零端点速度的悬停段；不是帧冻结或另一个场景。悬停期间扫描随用户滚动推进，反向时扫描沿原路径返回。
- 同一 shader、同一网格上用米制 `surfaceCoord` 绘制 1 km 格网与范围框。框为已加载 context DEM 的外包范围（约 4.7×12 km），不是模型推理结果，也不是宣称整框均有 0.6 m 影像。落点环和扫描是艺术辅助标记。
- 没有新增模型、纹理或全屏渲染缓冲。原 NAC/WAC 加载、卸载和缓存机制未改。
- 桌面悬停视场 48°，地形落在右侧，文字在左；手机为 86°、目标向南侧偏移，将走廊留在上方。视场、视线、展示光线均随相同平滑权重进入/退出。
- 极区相机代码与 PSR 材质代码未改变。旧影像再光照、法线过滤、瓦片混合、HDR 像素预算、地表岩石和阴影配置未改变。模拟悬停和展示光线不代表航天器动力学或真实历元照明。
- 高程走廊外的 WAC 区域影像在该高度仍能看出分辨率限制；未用锐化或生成纹理冒充 NAC 数据。

## 亲眼检查与修正

第一轮桌面走廊贴近页眉和导航，手机走廊上缘被裁切。增大专属于悬停段的视场，再为手机调整目标位置；第二轮手机截图能同时容纳走廊、标题、数据读数和导航。中间态离开后恢复原视场。

`check/` 与 `check-wide/` 为中间迭代；最终桌面全程以 `forward/`、`reverse/` 为准，手机中间态为 `mobile-final/34.5.png`。

截图名是**内部叙事百分比**，例如 `34.5.png` 对应实际滚动 **39.55%**，`53.5.png` 对应 **71.82%**。每个方向的 `frames.json` 同时保存实际滚动比例、相机位姿、月面数量、资源状态及控制台错误。全程 2% 内部步长，中间态 29–41% 使用 0.5% 步长，贴地和极区进一步加密；另外纳入各关键锚点。

浏览器使用自己启动的生产预览 4291，测试使用自动管理的独立端口 4292。未操作用户 5173 或其他开发服务。真实 Chrome / SwiftShader 验证画面、滚动与 WebGL，不作为用户硬件帧率测试。

全程正向复查额外发现原有短桌面窗口（1200×800）开场小字、终幕操作区靠近导航。仅对桌面高度 ≤900px 收起开场装饰小字与终幕尾注、上移终幕操作区。补拍内部 0–18% 和 92–100% 正反向帧，其他帧的渲染样式不受此修正影响；最终 frames.json 合并补拍结果。
